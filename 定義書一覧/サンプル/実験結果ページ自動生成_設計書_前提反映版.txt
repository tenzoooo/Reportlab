\
【設計書（前提反映・横断対応版）】
実験結果ページ自動生成（Dify＋docxtpl＋python-docx）
最終更新: 2025-09-13 (JST)

大前提
- 添付の実験書PDFには「実験結果」ページは含まれない（PDFは原則「実験方法」まで）。
- 「実験結果」ページはユーザー側が新規作成する。本設計では、その生成をAI（Difyワークフロー＋レンダラAPI）に委任する。
- Wordテンプレートは v3（中央揃え／Subdoc方式）を採用。
  - 表キャプション／図キャプションは中央揃え固定（CaptionCentered）。
  - 表は Subdoc 挿入（列数・行数が可変）。図は InlineImage。

テンプレートファイル
- 実験結果_テンプレ_v3_centered.docx（採用版）
- 参考: 実験結果_テンプレ_v2_subdoc.docx, 実験結果_テンプレ.docx

────────────────────────────────────────
1. 目的 / 成果物
────────────────────────────────────────
目的: 実験書PDF（方法まで）＋ユーザー提供の実験データ（Excel/CSV/画像）から、所定フォーマットの「実験結果」ページ(.docx)を自動生成する。

成果物（章番号 N とする）:
- 見出し1: 「N. 実験結果」
- 見出し2: 「N.i {実験名}」 ※必要に応じて「N.i.j」も（細分）
- 各実験ブロック
  * 簡単な説明（2–3文、常体）
  * 表（上キャプション=中央揃え、本文は可変列×可変行のSubdoc）
  * 図（画像、下キャプション=中央揃え）
  * 定量的コメント（約500字）：図表番号（図N.m/表N.k）を明示して論述

注: 図表番号はコード側で採番して文字列で挿入（WordのSEQは不使用）。

────────────────────────────────────────
2. 入出力（I/O）
────────────────────────────────────────
入力（必須以外は任意）
- pdf_manual (bytes|URL) …… 実験書PDF（方法まで収録）
- exp_tables[] (file[]) …… 実験結果（Excel/CSV、複数可）
- exp_images[] (file[]) …… 波形・スクショ等（PNG/JPG、複数可）
- logs[] (file[]|text) …… 測定ログ・メモ（任意）
- meta (object) …… student_name, student_id, dept, experiment_title, date_experiment, date_submit
- options (object)
  * force_chapter_number (int|null) …… 章番号を手動指定（抽出失敗時のフォールバック）
  * max_comment_len (int, default=500) …… 定量コメント最大字数
  * lang (str, default="ja") …… 用語・キャプション言語（将来多言語化を想定）

出力
- docx_bytes (bytes) …… 完成Word
- manifest.json (json) …… 採番・差し込みマップ、再現用メタ情報

────────────────────────────────────────
3. 章番号 N の決定（PDFは方法まで）
────────────────────────────────────────
前提: PDFに「実験結果」章は無い。よって N は「方法（手順）」の章番号の +1 とする。

手順（堅牢化）
1) 見出し候補抽出: 番号付き大見出し（全角/半角/ドット/ハイフン/丸数字を許容）を抽出。
2) “方法系”見出しの特定: 正規化した本文から、以下の語を優先順で探索（大文字小文字無視）。
   - 実験方法｜実験手順｜手順｜方法｜Procedure｜Method(s)
   - 存在しない系（ディジタル/マイコン/ロボット等）は「装置｜演習｜課題｜実施」を代替キーに採用。
3) N = M + 1（M は該当見出しの章番号）。
4) 失敗時: options.force_chapter_number を必須にする。

────────────────────────────────────────
4. 実験ユニット抽出と命名（N.i / N.i.j）
────────────────────────────────────────
- 実験ユニット i は、提供データのファイル名、シート名、列名、画像ファイル名、PDF本文の小見出し/キャプション語から推定。
- 例: 「RLC回路」「一次LPF」「PLL(N=16)」「MOSFET ID-VD」「CR微分」「高周波Q」「PID温度制御」「JK-FF」「同期カウンタ」「命令フェッチ」等。
- 細分 j（N.i.j）は、1つの実験iの中で条件/デバイス/回路型が複数ある場合に導入（例: フィルタの型別、PLLの分周比別、Q測定の素子別）。
- ユーザー上書き: experiments[].name / subidx を任意に上書きできるUI/入力を用意。

────────────────────────────────────────
5. 番号付けポリシー
────────────────────────────────────────
- 表: 章内通しで 表N.1, 表N.2, … （出現順）
- 図: 章内通しで 図N.1, 図N.2, … （出現順）
- 見出し: 「N.i {name}」＋（必要なら「.j」）
- 参照は本文中で「図N.m」「表N.k」に統一。SEQフィールドは使わない（更新ズレ回避）。

────────────────────────────────────────
6. 各実験ブロックの生成ロジック
────────────────────────────────────────
(1) 見出し: 「N.i（.j） {実験名}」を出力。
(2) 簡単な説明（LLM）: 方法の要点・測定の狙い・条件を2–3文で要約（常体、専門語OK、数式は不要）。
(3) 表（Subdoc）: Excel/CSVを解析し、ヘッダ行・単位を推定。列数・行数は任意。列幅は必要に応じて均等割/最大幅制約。キャプションは中央揃え。
(4) 図（InlineImage）: 画像を幅指定で挿入（Mm）。縦長/横長を考慮し、改ページを必要に応じて付加。キャプションは中央揃え。
(5) 定量コメント（LLM、~500字）: 下記メトリクスを引用しつつ、図表番号を明示して考察。測定値→指標→理論整合→原因推定→まとめ。

────────────────────────────────────────
7. メトリクス計算（分野横断の部品化）
────────────────────────────────────────
共通（表または時系列）
- 平均, 標準偏差, 最大/最小, ピーク検出, 立上り/立下り時刻, ゼロクロス, 傾き近似 等

アナログ回路（RC/RLC/フィルタ）
```latex
M_p = \\frac{V_{\\text{peak}} - V_\\infty}{V_\\infty},\\quad
t_r = t(0.9V_\\infty) - t(0.1V_\\infty),\\quad
\\tau_{RC} \\approx RC
```
- カットオフ: fc（-3dB）推定、傾き（dB/dec）、位相特性

MOSFET
- \(I_D\text{-}V_D\) 線形/飽和境界、しきい値近傍の勾配、飽和電流の比較

PLL
```latex
f_{\\mathrm{out}} = N\\,f_{\\mathrm{in}}
```
- ロック判定、過渡応答（立上り/オーバーシュート）

温度制御（PID）
```latex
y(t)=K_P e(t)+K_P\\frac{1}{T_I}\\!\\int e(t)dt + K_P T_D \\frac{de(t)}{dt}
```
- 立上り/整定/オーバーシュート、定常偏差の有無

高周波インピーダンス/Q
```latex
Q_{\\text{series}}=\\frac{\\omega L}{R},\\quad Q_{\\text{parallel}}=\\frac{\\omega C}{G}
```

ディジタル/マイコン/ロボット
- 伝搬遅延、セットアップ/ホールド余裕、状態遷移の整合、スループット/レイテンシ概算

────────────────────────────────────────
8. テンプレート仕様（v3 採用）
────────────────────────────────────────
- 見出し1: {{ chapter }}. 実験結果
- 実験ループ: {% for exp in experiments %}
  * 見出し2: {{ chapter }}.{{ exp.idx }}{% if exp.subidx %}.{{ exp.subidx }}{% endif %} {{ exp.name }}
  * 説明: {{ exp.description_brief }}
  * 表:  キャプション(中央): {{ tbl.label }}　{{ tbl.caption }}
          本体: {{ tbl.doc }}（Subdoc: 可変列×可変行）
  * 図:  画像 {{ fig.image }} + キャプション(中央): {{ fig.label }}　{{ fig.caption }}
  * 定量コメント: {{ exp.quant_comment }}
- ループ終端: {% endfor %}

備考
- 改ページはSubdoc側で制御（孤立見出しや図のはみ出しを防ぐ）。
- キャプション中央揃えはテンプレ内スタイル CaptionCentered を適用。

────────────────────────────────────────
9. Difyワークフロー（ノード定義）
────────────────────────────────────────
#  種別  名称/役割                       入力                                  出力
0  Code  PDF見出し抽出器                 pdf_manual                             manual_outline, raw_text
1  Code  章番号リゾルバ                  manual_outline, options.force_*        N
2  Code  データ資産インベントリ          exp_tables[], exp_images[], logs[]     assets_index（表/図/ログの索引）
3  Code  実験ユニット推定                assets_index, raw_text                  experiments[](skeleton: idx/name/subidx)
4  Code  メトリクス計算                  exp_tables[], logs[]                    metrics（実験ごと）
5  LLM   簡単説明ジェネレータ            experiments[i], raw_text, metrics       experiments[i].description_brief
6  LLM   キャプションジェネレータ        assets_meta, metrics                    tables[].caption, figures[].caption
7  Code  採番エンジン                    N, experiments[], assets_index          tables[].label, figures[].label
8  HTTP  Wordレンダラ（/render）         chapter=N, experiments[], meta          docx_bytes, manifest.json
9  Resp  成果返却                        docx_bytes                              —
※ ユーザー上書きノード（任意）: 名前/順序/見出しの手動修正UI → ノード7前に介在

────────────────────────────────────────
10. レンダラAPI（/render）
────────────────────────────────────────
POST /render
Request(JSON): 
- chapter: int
- experiments: array
  * idx, (subidx), name, description_brief
  * tables[]: { label: str, caption: str, doc: Subdoc }
  * figures[]: { label: str, caption: str, image: InlineImage }
  * quant_comment: str
- meta: object
Response: .docx バイナリ

ENV
- RENDERER_URL, MAX_COMMENT_LEN, PDF_ENGINE（"pymupdf"|"unstructured"|…）

────────────────────────────────────────
11. 採番アルゴリズム（手続き）
────────────────────────────────────────
1) N 確定（節3）。
2) table_no=1, fig_no=1 を初期化。
3) experiments を見出し順に走査し、出現順で
   - tables[].label = f"表{N}.{table_no}"; table_no+=1
   - figures[].label = f"図{N}.{fig_no}";   fig_no+=1
4) 本文の参照生成時は、上記ラベルを文字列で使用。

────────────────────────────────────────
12. エッジケースと回避
────────────────────────────────────────
- “方法系”見出しがPDFに無い → 補助キー（装置/演習/課題/実施）でMを推定 → N=M+1。最終的に force_chapter_number を利用可。
- 表が巨大 → Subdocを分割、列幅を均等割、必要なら横向きセクションを別Subdocで用意。
- 画像が多い/縦長 → 画像ごとに改ページ候補を挿入、キャプションの孤立を防止。
- データ欠落 → キャプションは生成するが、画像/表はプレースホルダ挿入で欠番を作らない。
- LLMのばらつき → 分野別プロンプト雛形をsystem化（次項）。

────────────────────────────────────────
13. LLMプロンプト雛形（要約）
────────────────────────────────────────
A) 簡単説明（Node#5）
- 2–3文、常体。方法の要点と測定対象のみ。図表番号はここでは出さない。

B) キャプション（Node#6）
- 表: 測定条件/変数/単位を含めて簡潔に（中央揃え）。
- 図: 波形/周波数応答/段階数などの条件を明記（中央揃え）。

C) 定量コメント（Node#5 or #8）
- 約500字、常体。図N.m/表N.kを必ず引用。測定値→指標→理論整合→原因推定→まとめ。

────────────────────────────────────────
14. テスト計画
────────────────────────────────────────
- 章番号抽出: “方法系”見出しがあるPDF/ないPDFでNが正に決まる。
- 表: 2×3 / 2×10 / 10×100 でも崩れない（Subdoc）。
- 画像: 複数・縦横混在でもキャプション中央・改ページが適切。
- 採番: 順序変更・細分追加でも章内通しの整合が保たれる。
- LLM出力: 図表番号の引用が常に含まれる。

────────────────────────────────────────
15. 変数（まとめ）
────────────────────────────────────────
必須: chapter, experiments[*].idx, experiments[*].name,
      tables[].doc（ある場合）, figures[].image（ある場合）,
      tables[].label, figures[].label, quant_comment
任意: subidx, meta.*, options.force_chapter_number, options.max_comment_len, lang
